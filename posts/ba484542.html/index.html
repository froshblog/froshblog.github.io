Hexo博客搭建所得

发表于 2026-02-11 分类于 个人笔记 ， 收获 本文字数： 1.2k 阅读时长 ≈ 1 分钟

我的博客技术实现架构：Hexo + GitHub + GitHub Pages + EdgeOne CND；本地使用obsidian进行博客管理和编写。

博客框架的了解

静态和动态的页面的区别

静态页面：内容通过本地电脑或构建服务器一次性将markdown文件转换为html页面。
动态页面：服务请没有现成的html文件，只有数据和模板。请求时，通过PHP等程序实时从数据库调取文章内容，再填入html模板，临时生成页面。

框架的认识

使用自然语言通过框架生成网页前端文件。

GitHub的认识及使用

微软旗下，全球最大的开源社区；一个基于Git的代码托管平台，但其核心功能不只是存代码，还有让协作变得可视化、流程化；并且提供多个好用的免费服务。如：GitHub Pages、GitHub Action等。

GitHub Pages

GitHub上的免费静态网页托管服务，可以让你随时发布你的静态网页。

GitHub Action

GitHub Actions 是 GitHub 官方提供的自动化工具，可通过自己编写脚本实现自动化。

典型场景使用

  • CI（持续集成）：每次 push 代码，自动运行测试、检查代码格式（ESLint）、构建项目，确保代码没问题。
  • CD（持续部署）：测试通过后，自动把项目打包、上传服务器，或者部署到 GitHub Pages / Vercel / 云主机。
  • 定时任务：比如每天早上 8 点爬虫抓取数据，自动生成新页面并提交。
  • 社区协作自动化：给 PR 打标签、自动欢迎新贡献者、关闭长时间未活动的 Issue。

限制

  • 私有仓库分钟额度：免费账号每月2000分钟
  • 单任务执行时长：每个job最长6个小时，超时终止
  • 工作流总时长：单次工作流运行最长35天
  • 缓存上传速率：每分钟最多200个新缓存条目

我想说的话

现在我的博客的工作流主要在本地执行，GitHub上只是托管前端代码和发布博客页面。以后想使用这个功能将工作流转移到GitHub上。

CDN的认识

通过这几天的学习，CDN主要使用了反向代理技术，让访客向CDN边缘节点获取页面。

EdgeOne使用反向代理技术，理论上是可以代理任何网站，以后想要尝试一下。

obsidian的使用

将obsidian作为我的博客管理器真不错。本身可以调用模板和创建位置自定义以及它的插件丰富，可以找到你想要的功能。

总结

这次博客搭建所得颇丰，无论是学习使用各个平台达到目的，还是在自定义博客时的CSS，js的些许知识学习，整体体验还是不错的，就是完成自定义博客后感觉没用必要再CSS，js上费时间，博客就是写文章的平台。
当然，这其中也遇见了很多问题，如：GitHub的连接问题导致无法发布到GitHub上，hexo环境变量问题，CDN如何配置，CDN如何优选等。
总体而言，这次的体验很充实，而关于这个博客的设置也暂时告一段落了，接下的时间我将着重再它的内容上了。
