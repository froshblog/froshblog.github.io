Hexo个人博客搭建

发表于 2026-01-15 分类于 个人博客 阅读次数： 本文字数： 5.9k 阅读时长 ≈ 5 分钟

引言

这是一个搭建个人博客的教程，也是我的学习笔记。希望帮助每个人能按照这篇文章的步骤从零开始搭建出一个个人博客。当然，我现在只是一个学习者，正在不断摸索的阶段，如有问题还请斧正。

关于博客的认识

现在我所搭建的是一个静态博客。它完全免费，不需要服务器，域名可有可无。
现代静态博客从技术实现架构看，有四个核心部分组成：博客生成框架（如Hexo,Hugo等）、文件托管平台（GitHub,gitee等）、站点部署服务（GitHub Pages,GitHub Actions,GitLab CI/CD,Vercel/Netlify等）、CDN加速服务（Cloudflare CDN、Vercel/Netlify等）。
这篇博客所使用的技术实现架构：Hexo + GitHub + GitHub Pages。这里站点部署服务之所以选择GitHub Pages而不是GitHub Actions，是因为我的博客是在本地电脑构建出前端文件(HTML/CSS/JS文件)上传至GitHub的，GitHub Actions的脚本需要运行在源码上；至于为什么没有CDN加速服务，是我还不知道怎么配置加速，后面我会将这个加上的。

写博客的好处

首先，博客是可以作为一个知识输出的端口，正所谓“学然后知不足，教然后知困”，写博客就是对知识的重新认识和回顾，加深对知识的理解；其次，博客输出是一个搭建个人数字资产，一个知识库，可以作为自己日后的重要材料；最后，博客可以帮助正在学习相关知识的人，结交志同道合的伙伴。

使用的工具及系统环境

这个教程的博客结构：hexo + github + github pages，没有使用CDN加速用户的访问，主要现在我还没有去学。使用hexo生成博客目录，再上传到GitHub托管代码，然后使用GitHub的免费静态网页托管服务-GitHub Pages将网站部署。

我个人的系统环境是Windows11，需要使用git命令。

git官网：https://git-scm.com/

安装流程默认即可。

Hexo博客框架

介绍

hexo是一个基于nodejs的静态博客网站生成器，作者是来自台湾的Tommy Chen，它能作为多名博主的博客框架主要有以下优点：

  • 支持MarKdown语法，编辑简单，排版优美
  • 能快速生成和渲染上百页面
  • 部署简单，接口简单
  • 兼容于各大主流操作系统
  • 社区主题和插件丰富，解决问题的参考材料多

环境配置

hexo是基于nodejs的，需要它的相关环境，可以从官网直接下载

https://nodejs.org/zh-cn/

下载后如没有特殊配置，全程默认即可。最后查看版本信息来确认环境配置信息：

能够正常看到版本信息，说明环境配置已经完成。如果没有看到，提示”无法将什么识别为~”，可能是你的系统变量出现问题，可以通过手动配置系统变量解决。这里为了节省篇幅，使用简洁的方式打开系统变量：

  1. 在Windows搜索框输入“环境变量”，快速访问到相关页面进行相关设置

  2. 点击环境变量，无论是用户变量还是系统变量重点看它们的Path，查看里面是否有“nodejs”和“npm”的词样

  3. 没有，选择任意一个变量进入Path新建变量

还有一点需要注意，npm默认的官网源执行时加载慢，或者执行命令时报错。可以通过以下方式将源设置为国内的淘宝镜像源。

目录结构如下：

各部分的含义：

  • _config.yml
    • 为全局配置文件，网站的很多信息都在这里配置，比如说网站名称，副标题，描述，作者，语言，主题等等。具体可以参考官方文档：https://hexo.io/zh-cn/docs/configuration.html。
  • scaffolds
    • 骨架文件，是生成新页面或者新博客的模版。可以根据需求编辑，当hexo生成新博客的时候，会用这里面的模版进行初始化。
  • source
    • 这个文件夹下面存放的是网站的markdown源文件，里面有一个_post文件夹，所有的.md博客文件都会存放在这个文件夹下。现在，你应该能看到里面有一个hello-world.md文件。
  • themes
    • 网站主题目录，hexo有非常丰富的主题支持，主题目录会存放在这个目录下面。
    • 我们后续会以默认主题来演示，更多的主题参见：https://hexo.io/themes/

Github Pages部署

GitHub上免费快捷的静态网站托管服务，能部署两种类型站点：个人站点、项目站点

个人站点：每个用户只有1个，仓库名有严格要求（仓库名称.github.io）,访问地址是https://仓库名.github.io

项目站点：数量无限，仓库名没有限制，访问地址是https://github用户名.github.io/仓库名

关于网址长的问题自然有解决方法：配置自定义域名

部署流程：

进入仓库页面——>Settings——>Pages——>选择部署方式为”Deploy from a branch”

  1. 进入博客网站仓库设置界面

  2. 进入Pages服务页面

  3. 选择构建部署方式为：Deploy from a branch

  4. Branch（分支）:分别选择main， /(root)，然后save保存，等待几分钟刷新即可

  5. 验证

    访问 网址https://username.github.io查看效果

这里之所以不选则GitHub Actions部署，是因为我们这个博客是在本地构建出静态文件，然后将这些静态文件上传到GitHub上的，actions服务的工作流脚本需要在博客根目录下执行，并且使用’hexo deploy’上传部署是执行的强制推送，会覆盖原来的仓库的文件，导致工作流脚本缺失。
